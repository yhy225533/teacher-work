# V1.10 · 走查反馈修复（备课状态保持 + 资料移除可达性 + 生成类型并排）

产品负责人 2026-09-09 会话立项。背景：V1.9 交付后使用反馈五项分析（问题 2 定位为中转站限流，本版本**不含**；问题 3 为 Office/PDF 应用内渲染大方案，本版本**不含**，另立 V1.11，见 §8）。本版本修复其中三项：问题 5（备课选择状态丢失，真 bug）、问题 1（资料移除入口可达性，V19-B 收纳副作用）、问题 4（生成类型单选收窄，V19-A 交互回退）。

## 1. 目标

1. **问题 5（bug）**：备课工作台里"生成依据/补充参考"的手工勾选状态，经「＋ 外部资料」「＋ 素材库」往返后必须保持——✕ 掉的不回来、勾好的不丢失；
2. **问题 1（交互）**：课件资料树节点 hover 出现 ✕ 快捷移除（带确认）；树顶「批量管理」模式可勾选多份一次性移除（应对快速建课误导入一批）；历史版本折叠块每行补移除入口；
3. **问题 4（交互回退）**：`prepMode === 'new'` 时生成类型恢复三个并排按钮（讲义/例题/作业），可连续点出多份独立文件——恢复 V1.2 体验，单次生成合同（`kind` 单值）不变；
4. 零 migration、零新依赖、零新 IPC；不重做任何已冻结语义。

## 2. 问题 5 修复方案（V110-A）

### 根因（2026-09-09 代码核实）

- 勾选状态 `selectedReferenceFileIds` 是 DraftPanel 局部 state（draft-panel.tsx:112），不持久化；
- 「＋ 外部资料」走 `onOpenExternal` → `setActiveItem('外部资料')`（App.tsx:215-219），App 按 activeItem 条件渲染 → **教学内容页分支整体卸载**；
- 回来后 DraftPanel 重挂载，初始化 effect（draft-panel.tsx:293-312）重跑：无 md → `new` 模式**全选本课资料**（✕ 掉的回来）；有 md → `single` 模式**清空参考**（勾好的丢失）；
- 素材库路径同构（`onOpenMaterials`）。

### 修复：picker 往返不卸载教学内容页

App.tsx 已有 `externalPickerOpen` / `materialPickerOpen` / `prepContext` 三个 state 专为该往返服务，但只用于切换目标页的内部形态，教学内容页本身仍被卸载。修复为**渲染保活**：

```
{activeItem === '外部资料' && externalPickerOpen && prepContext !== null ? (
  <>
    <TeachingContentPage target={teachingContentTarget} … />
    <ExternalLibraryPanel context={prepContext} picker … onHidden={returnToPrep} />
  </>
) : …原条件渲染…}
```

- picker 打开期间，教学内容页（含 DraftPanel 全部局部状态）保持挂载；picker 页面以覆盖层/旁挂形式呈现，不再占用 `activeItem` 分支；
- 关闭/选完 → `returnToPrep` 收起覆盖层，DraftPanel 状态原样保留；
- DraftPanel 挂载期间通过 `files.onContentChanged` 感知新导入文件——为此 Main 侧补一行通知（见下）；
- **附带 Main 小修**：`external-library-ipc.ts` 的 `copyToLesson` / `importToLesson` 在 `enqueueIndex` 后补发 `notifyContentChanged`（既有 `files:content-changed` 广播，V19-F 冒烟发现的 chips 计数停更在此前已用 renderer 兜底修复；本次在事件源头补齐，renderer 兜底线保留不删——双保险且语义更准）。这属于既有广播的补发，不是新通道。

### 不做的方向

- 不做选择状态持久化到 DB/localStorage（组件内保活已根治，持久化是过度设计）；
- 不改 `reconcileSelectedLessonFileIds` 的"新文件自动入选择"规则（V1.7.2 设计语义，且修复后 reconcile 只在文件集合变化时跑，行为正确）。

## 3. 问题 1 修复方案（V110-B）

现状：「从本课移除」在 ⋯ 菜单底部红区（V19-B/D57），五步路径且单份。修复三层，全部复用既有 `files.softDeleteFile` 通道，零新 IPC：

1. **树节点快捷 ✕**：`MaterialTreeNodeRow` hover 显示 ✕（仅 `editable` 且非当前讲义当前版）；点击 = 同 ⋯ 菜单同款确认弹窗（"外部/素材库原件不受影响"文案不变）+ softDeleteFile；当前讲义当前版（版本链最新）仍只能走 ⋯（保护误删唯一正文）；讲义组历史版本行的 ✕ 走历史版本移除（见 3）；
2. **批量管理**：树标题行加「管理」toggle；开启后树进入多选态（复用 `selectedFileIds`/checkbox 渲染），底部「移除所选 (N)」按钮 + 一次确认（列文件名清单，外部原件不受影响文案）；确认后逐份 `softDeleteFile`（Main 侧无批量通道，循环调用，N 份时串行 await）；再点「完成」退出管理态；
3. **历史版本移除**：`🕘 历史版本` 折叠块每行加 ✕（同款确认：删的是本课副本，外部原件不涉及——历史版本都是 managed 副本）；版本链"当前版"不在历史折叠块内（天然受保护）。

**禁改**：softDeleteFile 软删语义、外部根目录只读、已结束课程 readOnly 不出现任何移除入口（管理 toggle 一并隐藏）、`..` 菜单既有红区入口保留（多入口并存，菜单兜底）。

## 4. 问题 4 修复方案（V110-C）

现状：`prepMode === 'new'` 时生成类型是单选下拉（draft-panel.tsx:1409-1415），一次只能一种。修复：

- 下拉撤除，恢复 V1.2 形态：`prepMode === 'new'` 时在「✦ 发送」旁并排渲染三个 secondary 按钮「讲义 / 例题 / 作业」（`DRAFT_KINDS` 数组 map，V1.2 同款）；
- 点任一按钮 = 以该 kind 直发（`generate(kind)`），生成中（busyAction/improveBusy）三按钮全部禁用、所点按钮显示「生成中…」；完成后可立刻点下一个（连续生成，每次独立 note）；
- 「✦ 发送」保留为 single/lesson 模式的主操作（改这份讲义/整个课件包重做走方案确认流，与 new 模式的直生成分流）；
- 合同零改动：`drafts.generate` 的 `kind` 仍单值、一次一请求；连续出三份 = 用户连点三次，每次独立 requestId/note（V1.2/V1.5 既有行为）；
- `improveKind` state 与 `plannedDraftKind` 推导撤除（new 模式不再需要，single/lesson 的 kind 推导保留）。

## 8. 非目标与后续（V1.11 候选：Office/PDF 应用内渲染，问题 3）

2026-09-09 调研结论（供后续立项，本版本不实施）：

- **三类文件分层**（产品负责人提出）：自产文件（讲义/习题/作业，基本 md——天然可预览，不涉及）；**完整卷子**（word 版——需保版式预览 + AI 可引用内容）；**参考文件**（杂格式——需内容理解，版式次要）；
- **候选技术**：PDF = pdfjs-dist（Mozilla，Apache-2.0，92M 月下载，v6.3 活跃）经 react-pdf（React 19 支持）；Word 版式 = docx-preview（Apache-2.0，仅 jszip 依赖，DOM 构建型渲染）；Electron 内置 file:// viewer 因绕开"内容走 IPC"安全边界不推荐；
- **廉价先行项（比新依赖更优先）**：MinerU 增强文本与 officeparser 抽取文本目前**只进搜索索引**（mineru-service.ingestMarkdown 只调 search.indexFile；AI 备课参考 readScopedTextParts 走 readContent 的 mime 白名单，office/pdf 全部跳过）——把既有抽取文本接到 readContent 文本分支（如 kind:'text' 回退增强 md），即可让 AI 参考读到卷子/参考文件内容，零渲染依赖；
- 解除"渲染层零新依赖"冻结需产品负责人在 V1.11 立项时明确确认。
