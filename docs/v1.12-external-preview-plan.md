# V1.12 方案：外部资料应用内预览 + docx 内嵌图片修复

- 日期：2026-09-10（立项）
- 背景：V1.11 交付后产品负责人实测反馈两个问题——①**带内嵌图片的 docx 预览时图片不显示**（文字正常，图片全部空白）；②**同一文件在备课页（课次资料阅读器）能预览，在外部资料页却完全看不到内容**。
- 归因（已逐行核实，见 §2）：①docx-preview 默认 `useBase64URL: false`，内嵌图片走 `URL.createObjectURL(blob)` 生成 `blob:` URL，而 CSP `img-src 'self' data:` 不含 `blob:`，图片被 CSP 静默拦截；②外部资料页（V1.1 `external-library-panel.tsx`）从未有过预览能力——纯元数据 + 按钮面板，V1.11 只把预览接到了课次资料阅读器。
- 范围决策：①是 V1.11 交付缺陷，属维护增量语义；②是范围扩展（新载荷通道 + 面板 UI 改造）。经产品负责人 2026-09-10 授权（"解决一下"），合并为增量 **V1.12** 一并实施，避免两轮走查。①的修复并入本版第一个节点（不再单出 V1.11.1 标签，避免标签碎片——两个修复在同一个冒烟里验收最经济）。

## 1. 目标

1. docx 预览显示内嵌图片（含 png/jpg 内嵌于 Word 的试卷图、几何图）；
2. 外部资料页（独立导航 + 备课跳转两处挂载点）能对**已登记根目录内**的 PDF / docx / md / 图片 / 文本文件直接预览——不复制、不导入、不改动原文件；
3. 预览失败的文件仍有「打开文件」（系统应用）逃生门；
4. 安全边界零放松：Renderer 不接触路径；预览纯只读（零写入、零备份、零索引、零 files 表登记）；外部资料路径不得逃逸已登记根目录。

## 2. 归因记录（实施前核实）

### 问题 ①：docx 内嵌图片被 CSP 拦截

- `node_modules/docx-preview/dist/docx-preview.mjs:1222-1225`：`blobToURL()` 在 `useBase64URL: false`（默认，`:3970`）时返回 `URL.createObjectURL(blob)`；
- `src/renderer/index.html`：CSP `img-src 'self' data:` —— `blob:` 不在白名单，每个内嵌 `<img src="blob:...">` 都被拦（控制台可见 CSP violation，图片渲染空白）；
- V1.11 冒烟 fixture 是纯文字 docx，未覆盖带图场景——测试缺口如实记录。
- **修法**：`renderAsync` 选项加 `useBase64URL: true`——内嵌图改走 `data:` URL（CSP 已允许 `img-src data:`），**不改 CSP**；data URL 随 DOM 释放，无 blob URL 需手动 revoke 的内存语义。一行产品代码 + 带图 docx fixture 测试。

### 问题 ②：外部资料页无预览能力

- `src/renderer/external-library-panel.tsx:406-465`：选中文件只渲染元数据（面包屑/图标/类型/大小/修改时间）+ 三按钮（保存到素材库/用于本次备课/打开文件/所在文件夹）+ V1.1 时代说明「V1.1 不模拟 Word、PowerPoint 或 PDF 的高保真显示」；
- 既有通道无内容读取能力：`EXTERNAL_LIBRARY_IPC_CHANNELS` 七通道（get/choose root、listChildren、openFile、showInFolder、copyToLibrary、copyToLesson）都是元数据/动作，没有 read 类；
- V1.11 预览链只挂在 `lesson-material-reader.tsx`（课次资料树），其数据源是 `files:read-content`（managed 文件 fileId 查询）——外部资料不在 files 表，走不通。

## 3. 外部资料预览的通道设计（D70）

**新增单条 IPC 通道** `external-library:read-preview`（载荷通道，与 V1.9 `export:get-print-payload` 的"Main 组装、单次响应"模式同构）：

- 请求：`ExternalPathRequest`（rootId + relativePath，既有守卫复用）；
- 响应：`ExternalFilePreview` 新合同类型——与 `ManagedFileContent` 同构的四分支（text/image/binary/unsupported），但 **`file` 字段换成轻量元数据** `{ name, mimeType, sizeBytes }`（不含 fileId——外部文件不在 files 表，没有托管 ID）：

```ts
export type ExternalFilePreview =
  | { readonly kind: 'text'; readonly name: string; readonly mimeType: string; readonly sizeBytes: number; readonly content: string }
  | { readonly kind: 'image' | 'binary'; readonly name: string; readonly mimeType: string; readonly sizeBytes: number; readonly dataUrl: string }
  | { readonly kind: 'unsupported'; readonly name: string; readonly mimeType: string; readonly sizeBytes: number; readonly message: string }
```

- **MIME 判定复用 V1.11 语义**：由 extension 推导（外部资料无登记 MIME，用 `mimeTypeForName` 同表——Main 侧新增对扩展名的映射，与 managed 侧 `knownTypes` 保持一致的白名单：text/* 前缀族 + application/json → text；image/* → image；application/pdf + docx MIME → binary；其余 unsupported）；12MB 上限沿用（超限 unsupported + 提示走系统打开）；
- **路径安全**：复用 `ExternalLibraryService.resolveEntry`（realpath + within-root 断言 + R_OK 检查）——预览读取必须经 `getFilePath` 同款解析，**绝不直接拼路径读文件**；
- **纯只读**：不写 files 表、不入 objects、不进备份/索引、不发 contentChanged；响应不含绝对路径。

## 4. 外部资料面板 UI 设计（D71）

`ExternalEntryDetails`（文件选中态）改造为「预览优先」：

1. **可预览文件**（text/image/binary——按扩展名白名单判定，树节点渲染前就知道 extension）：显示预览区 + 保留操作行（保存到素材库/用于本次备课/打开文件/所在文件夹不变）+ 预览下方逃生门提示行（「需要打印或另存？→ 打开文件」仅 pdf/docx 显示，与课次阅读器一致）；
   - 预览区复用既有组件：binary+pdf → `PdfPreview`；binary+docx → `DocxPreview`；image → `<img dataUrl>`；text → md 用 `MarkdownDocument`（外部资料 md 与课次 md 同渲染面）、纯文本用 `<pre>` 限高滚动；
   - `.md` 的 text 预览走 MarkdownDocument 与课次阅读器保持一致；
2. **不可预览文件**（.doc/.pptx/.xlsx 及其他）：保留现有元数据卡 + 说明文案改为「这类文件工作台内暂不预览，可用系统应用打开」；
3. **加载失败**（根目录更换/文件移动/权限）：inline-error + 打开文件按钮仍可用（既有 openFile 通道不动）；
4. 加载语义：选中文件即请求预览（`useEffect` on selectedEntry），切换文件自动重载，文件夹选中不触发预览（保持现有元数据卡）；
5. V1.1 说明文案「V1.1 不模拟…」退役，替换为上述真实能力说明。

**备课跳转模式**（prepContext ≠ null，pick overlay）下同样生效——老师在外部资料里挑资料时当场能看到内容，不再需要复制进课次才能看。

## 5. 安全边界复核清单

- Renderer 不接触路径（预览载荷经 Main 组装，preload 守卫 `isExternalFilePreview` 过滤）；
- 预览纯只读（零写入/零登记/零备份/零索引/零 contentChanged）；
- 路径不逃逸（resolveEntry realpath + within-root 断言复用，拒绝越界与符号链接逃逸）；
- 12MB 上限（超限 unsupported，不炸内存）；
- CSP 零改动（docx 图片改 data: 走既有 `img-src data:` 白名单）；
- 零 migration、零新依赖；**新 IPC 仅此一条** `external-library:read-preview`；
- 外部资料原文件保持只读（不覆盖、不移动、不删除——AGENTS.md 红线）；
- renderer-boundary 测试继续守住：预览组件全部静态导入（复用 V1.11 的 DOMMatrix 占位基建）。
