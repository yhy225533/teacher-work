## 4. V111-D 期间发现的渲染缺陷与修复（如实记录）

冒烟不是形式门——本节点通过真实渲染断言发现了两处实现期未暴露的缺陷，均已在 V111-D 内修复并复跑验证：

1. **pdfjs worker 版本失配**：`new URL('pdfjs-dist/build/pdf.worker.min.mjs', ...)` 在本仓库解析到顶层 pdfjs-dist **v6.2.108**（officeparser 依赖 override 固化），而 `import { pdfjs } from 'react-pdf'` 的 API 是其内嵌 **v5.4.296**——运行时报 `The API version "5.4.296" does not match the Worker version "6.2.108"`。修复：workerSrc 深路径改指 `react-pdf/node_modules/pdfjs-dist/build/pdf.worker.min.mjs`（经 react-pdf exports `"./*": "./*"` 解析到其配套 v5 worker）。该陷阱由冒烟暴露（此前自动测试与 build 均无法发现 worker 与 API 的运行时配对问题），并已把该约束写进 pdf-preview.tsx 注释与钉测。
2. **react-pdf file 载荷引用竞态**：`file={{ data: ... }}` 字面量在每次重渲染时都是新引用，react-pdf 以 file 引用为重载键——ResizeObserver 宽度更新/pageCount 设置会取消进行中的加载并重载，与加载完成竞态，表现为 Document 卡「正在打开 PDF…」永不收敛（时序不定，窗口 resize 亦会触发，属真实产品缺陷而非冒烟脚本问题）。修复：`const file = useMemo(() => ({ data: dataUrlToUint8Array(dataUrl) }), [dataUrl])`，按 dataUrl 记忆化；钉测补 `useMemo`/`file={file}`/禁字面量三条断言。

另：冒烟像素断言演进为 alpha 感知（透明像素 RGB 读作 0,0,0 会假阳性「非空白」）+ 排除 canvas 默认 300×150 占位尺寸；fixture 墨迹改为填充矩形（不依赖未内嵌的 Helvetica 字形渲染）。这些是断言精度修正，非产品代码改动。

## 5. 安全边界复核

- **内容仍走 IPC**：Renderer 不接触文件路径；binary dataUrl 由 Main 读取组装（与 image 分支同构），Renderer 只解码渲染；
- **零新 IPC 通道**：`files:read-content` 既有通道响应合同扩展（binary 分支），载荷通道 sender 校验不变；
- **无脚本执行面**：pdfjs 双 layer 关闭（无文本层/注解层 → 无链接跳转面）；docx-preview 为 DOM 构建型渲染（无脚本执行）；
- **白名单收口**：仅 `application/pdf` 与 docx MIME 进 binary 分支；.doc/.pptx/.xlsx/任意其他二进制维持 unsupported + 系统打开逃生门；
- **12MB 上限沿用**：超限仍走既有 unsupported 提示（不变）；
- **依赖白名单（D69）**：仅 react-pdf + docx-preview 两个直接依赖（钉测 7 依赖排序全等守卫）；pdfjs-dist v5 为 react-pdf 携带的嵌套配套（非直接依赖），顶层 v6 仍属 officeparser 既有配置，零改动；
- **渲染器边界测试不变**：无 dynamic import/require/node: 模块（react-pdf 的静态导入经 DOMMatrix node 占位解决测试环境问题，不影响渲染端真实运行）；
- **零 migration、零数据改写**：本版无任何数据库/文件写入路径改动。
