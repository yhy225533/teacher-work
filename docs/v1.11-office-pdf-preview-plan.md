# V1.11 · Office/PDF 应用内预览（走查反馈问题 3）

产品负责人 2026-09-10 立项（"我认为这个可以，你按照这个写方案，并且实现！"）。背景：V1.9 交付后使用反馈五项分析中的问题 3——Word/PDF 无法在应用内渲染，`readContent` 只支持文本与图片，Word/PDF 一律 `unsupported` 退系统应用。V1.10 方案 §8 留档了 2026-09-09 的调研结论（三类文件分层 + 候选技术 + 廉价先行项），本版本按该调研落地：**PDF 用 pdfjs、Word(docx) 用 docx-preview，应用内点开即看**。

## 1. 目标

1. **PDF 预览**：课件区/资料阅读器点开 `application/pdf` 资料直接在应用内渲染（连续滚动、页与页清晰分页），不再退"用系统应用打开"；
2. **Word 预览**：点开 `.docx` 资料直接在应用内渲染接近原版式的文档（段落/表格/图片/页眉脚），不再退"用系统应用打开"；
3. **readContent binary 合同扩展**：既有 `files:read-content` 通道响应新增 `binary` 分支（与 `image` 分支同构的 dataUrl 载荷），**零新 IPC 通道、零 migration**；
4. **依赖冻结解除（仅限本版白名单）**：新增 `react-pdf`（含其依赖 `pdfjs-dist`）与 `docx-preview`（含其依赖 `jszip`）两个直接依赖——2026-09-09 调研结论经产品负责人 2026-09-10 确认；
5. 超限文件（> MAX_PREVIEW_BYTES 12MB）、`.doc`/`.pptx`/`.xlsx` 等其余二进制类型维持既有 `unsupported` + 系统打开路径不变；所有已冻结语义零改动。

## 2. 调研结论（2026-09-09 GitHub 核实，选型依据）

## 3. readContent binary 合同（V111-A）

`src/shared/file-contracts.ts` 的 `ManagedFileContent` 联合新增第四分支（与 `image` 分支同构）：

```ts
| {
    readonly file: ManagedFileRecord
    readonly kind: 'binary'
    readonly dataUrl: string   // data:<mime>;base64,<...>
  }
```

- **Main 分支判定**（`managed-file-service.readContent`）：`stats.size ≤ MAX_PREVIEW_BYTES` 且 `mimeType ∈ { 'application/pdf', docx MIME }` → 返回 `binary` dataUrl；其余路径（image/text/unsupported/超限）逐字节不变；
- **守卫演进**：`isManagedFileContent` 增加 `binary` 分支（`kind === 'binary'` 时要求 `isNonEmptyString(dataUrl)` 且前缀 `data:`）；preload 既有 `readContent` 通道零改动（守卫即过滤器）；
- **渲染端解码**：dataUrl → ArrayBuffer 一行工具（`fetch(dataUrl).then(r => r.arrayBuffer())` 或 atob 手转），供 pdfjs/docx-preview 消费；
- **合同测试**：新增 binary 往返（pdf/docx 各一）+ 超限仍 unsupported + image/text 分支零回归。

## 4. PDF 预览（V111-B）

- 新组件 `src/renderer/pdf-preview.tsx`：react-pdf `<Document file={Uint8Array}>` + `<Page>` 连续滚动渲染（宽度适配阅读器栏宽，`renderMode` 默认 canvas）；worker 经 Vite `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url)` 配置（react-pdf 官方推荐路径，electron-vite renderer 即纯 Vite）；
- 加载/失败态：react-pdf onLoadError → inline-error + 「用系统应用打开」逃生门保留；
- `LessonMaterialReader` 渲染分支：`content?.kind === 'binary'` 且 `file.mimeType === 'application/pdf'` → `PdfPreview`；
- 样式：阅读器滚动区内分页白底、页间距、页阴影（styles.css 新增 `.pdf-preview` 一组，窄窗零破版）；
- **安全**：不启用外部链接跳转（pdfjs 注解层点击由 `applyWindowNavigationGuard` 拦截 window.open，既有守卫）；pdfjs-dist 历史有 CVE，跟随上游补丁升级纳入维护惯例（依赖锁 ^ 范围 + 版本记录在案）。

## 5. Word(docx) 预览（V111-C）

- 新组件 `src/renderer/docx-preview.tsx`：`docx-preview` 的 `renderAsync(arrayBuffer, container)` 一次性渲染到受控容器 div；卸载时清空容器；失败 → inline-error + 「用系统应用打开」；
- `LessonMaterialReader` 渲染分支：`binary` 且 docx MIME → `DocxPreview`；
- 样式：`.docx-preview` 容器限宽居中、白底、内部表格/图片自适应（docx-preview 自带 `.docx-wrapper` 样式，外层只做尺寸约束与背景）；
- **范围边界**：仅 `.docx`（Office Open XML）；`.doc`（legacy 二进制）、`.pptx`、`.xlsx` 本版不渲染（docx-preview 不支持），维持 unsupported + 系统打开；
- **安全**：docx-preview 为 DOM 构建型渲染（不 innerHTML 注入执行脚本）；docx 内嵌图片走 blob 内存对象，不落盘。

## 6. 安全边界复核（V1.11 门禁项）

- Renderer 仍不接触文件路径：binary 载荷经既有 `files:read-content` IPC 由 Main 读取返回（与 image dataUrl 同路径），零新通道、零迁移、零白名单外访问；
- 不可信输入渲染：pdf 链接跳转被既有窗口导航守卫拦截；docx DOM 构建无脚本执行；两者均不产生文件系统写；
- API Key/秘密零接触；渲染纯本地（pdfjs/docx-preview 全离线，无网络请求）；
- 12MB 预览上限沿用——防超大文件拖垮 IPC 与渲染内存。

## 8. 非目标与已知限制

- `.doc`（legacy MS Word 二进制）、`.pptx`、`.xlsx` 应用内渲染（无成熟浏览器端方案：pptx 渲染无库、xlsx 属表格 UI 另一形态；后续按需另立项）；
- PDF/Word 的**编辑**（本版只读预览；编辑仍仅 md——D29/MdEditor 冻结语义不动）；
- 从预览打印/导出 PDF（V1.9 导出链只面向 md 课件，D48–D54 冻结面不动）；
- 缩放工具栏/缩略图侧栏/文本选择复制（最小可用预览先行，走查反馈驱动迭代）；
- **AI 参考内容线**（MinerU/officeparser 抽取文本接通 readContent 文本分支——v1.10 方案 §8"廉价先行项"）牵扯搜索索引存储结构，超出"渲染预览"版本边界，记后续候选；
- 中转站 429（问题 2）不在本版（V1.10 立项时已定位应用侧不改）。
