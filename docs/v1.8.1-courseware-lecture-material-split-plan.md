# V1.8.1 · 课件区讲义/材料分组（方案 A）与“设为讲义底稿”

产品负责人 2026-09-06 会话立项。背景：外部资料经“复制到本课”导入课次后，与 AI 生成的课件版本混在课件区平铺，无法区分“上课用的讲义”与“引用/参考材料”。真实数据佐证：高馨云第12讲挂 1 份真讲义（题目.md 38KB）、2 份答案核对 md、13 张题图、1 份外部 docx 试卷，全部同权重平铺；全库 0 个 AI 版本文件、69 个外部导入 md——老师的实际工作流就是“外部 md 当讲义”。

交互示意与视觉基准：`tmp/mockups/lesson-courseware-split.html`（本地不入库）。产品负责人 2026-09-06 拍板：“左侧这个可以！”= 方案 A（一棵树两段分组）。方案 B（讲义/材料两卡并列）未采纳。

## 1. 目标

1. 课件区文件树把本课文件分成两组：**📘 本课讲义**（上课正文，可修改可出版本）与 **📎 本课材料**（来源与参考，只读+可移除）；
2. 材料区的外部导入 md 可以一键**“设为讲义底稿”**，正式纳管进版本链，成为“当前讲义”；
3. 讲义组的历史版本（` · 第 N 版.md` 旧版）仍折叠展示，规则不变；
4. 不破坏任何已冻结语义：V1531-A 的“最新版+源文件+图片并列”、D27 的“任意 md 可 AI 二改”、D29 的“编辑另存新副本”、V1.7.2 D34 的“课件分区结构不动”。

## 2. 判定规则（数据层，零迁移零回填）

分组纯靠现有文件名约定，不新增数据库列、不回填历史数据：

| 文件 | 分组 | 依据 |
|---|---|---|
| `xxx · 第 N 版.md`（最新版） | 本课讲义 · 当前讲义 | 既有 `lessonVersionPattern`（lesson-prep-context.ts） |
| `xxx · 第 N 版.md`（旧版） | 讲义组下方“🕘 历史版本”折叠块 | 既有 `classifyLessonCoursewareFiles().history`，展示不动 |
| `xxx（编辑版）.md` | 本课讲义 | V17-C 编辑副本命名约定 |
| 其余一切挂课文件（外部 md、docx/pdf、图片） | 本课材料 | 兜底分组 |

“设为讲义底稿”动作 = 对选中的材料区 md 调用新的 Main 方法：生成 `原名 · 第 1 版.md` 副本（沿用 writeVersion 的课次锚定版本号规则），挂到本课；原件保持不动（材料区仍显示）。该动作不修改任何现有文件行（新增副本文件行，符合“绝不覆盖原件”）。

## 3. 展示规则

- `LessonMaterialTree`（课件区左侧目录）改为分组渲染：讲义组在前、材料组在后；两组用 `material-reader-tree-group` / `material-reader-tree-group-title`（样式已在 styles.css 中存在，此前无消费方，本版本启用）；
- 讲义组内文件带“当前”徽标（唯一当前讲义；无版本链且未提过底稿时讲义组为空并显示引导文案）；
- 材料组文件带来源小标签（外部/素材库，复用 `lessonFileSourceLabel`；该函数已存在，本版本首次渲染进课件区树）；
- 备课工作台（draft-panel）参考行的 `lessonFileSourceLabel` 徽标、`ScopeFileList`、AI 修改准入全部不动（V1.7.2 D33/D34）；
- 右侧正文阅读、题图跟随正文（引用即挂到对应文档下）、MinerU 增强解析、编辑入口全部不动。

## 5. 安全边界复核

- `setLessonFileRole` 只接受 fileId（受控 UUID，经 isFileIdRequest 同形校验），不接受路径/SQL；
- 新文件经 `createTextObjectAndRegister`（临时文件+原子重命名）落盘，绝不 UPDATE 目标行；
- 原件不动：提讲义后材料区原件保留（与 writeVersion 的版本链分支同构）；
- Renderer 只通过 preload API 调用，不触碰 Node/文件系统。
