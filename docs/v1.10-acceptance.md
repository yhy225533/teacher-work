## 4. 冒烟脚本设计说明（如实记录）

- new 模式的依据必须是非图片、非 md 文件（`isSelectableLessonPrepFile` 排除 image/*；md 会把课次拉回 single），故用 text/plain 的 txt 作依据——这正是产品语义（冷启动课次用参考资料 + 要求从零生成）；
- 历史版本行需版本链命名（` · 第 N 版.md`）才入 history 组，故经真实 UI 通道造链：setLessonFileRole（设为讲义底稿，第 1 版）→ writeVersion（第 2 版）；plain md 直接 writeVersion 只产生「（编辑版）」不入历史组——与 V1.8.1 分组语义一致；
- 全部确认弹窗（useAppDialog）经真实 DOM 驱动（`.modal-card[role=dialog]` + danger 按钮），非 IPC 直调；
- 冒烟脚本不入库（tmp/ 忽略）；如需复跑，脚本留在本地 `tmp/v110-smoke/run-smoke.mjs`。

## 8. V1.10.1 维护增量证据（V1101-A / D65，2026-09-09 追加）

V1.10 四节点完成后、走查确认前，产品负责人报告移除资料瞬间连出两条 error 日志（`ipc.file_request_failed` files:read-content"文件已删除，请先恢复。" + `ipc.mineru_request_failed` mineru:get-status"文件不存在或已删除。"，同一渲染帧，随后自愈）。经授权按 V1.5.3.1 先例修复为维护增量 V1.10.1（决策 `implementation-tasks/V1_10_DECISIONS.md` D65），本节追加证据，上文 V110 历史记录不改写。

- **根因**：单份 `removeFile` / 批量 `removeSelectedFiles` 旧序「先 `setSelectedFileId('')`、后 `await reload()`」——清选中渲染瞬间 `displayFiles` 仍为旧列表（含已软删文件），`LessonMaterialReader` 自动重选 effect 从旧列表把刚删文件重新选中，连发两条注定失败的 IPC；主进程守卫按设计拒绝。竞态非 V1.10 新引入（`removeFile` 旧序早于 V110-B），D62 三层移除入口提高了触发概率。
- **修复**：两处调用点改为「软删 → 先 `await reload()` → 函数式按需清选中」（`(current) => current === fileId ? '' : current` / `(current) => manageSelectedIds.includes(current) ? '' : current`）——列表先落新值，自动重选只命中有效文件；函数式更新保证 await 期间用户改选不被旧闭包覆盖。三条移除入口（树 hover ✕ / ⋯ 菜单 / 历史 ✕）全部汇入 `removeFile`，批量入口汇入 `removeSelectedFiles`，无第三条路径。
- **明确不动**：阅读器自动重选逻辑、主进程守卫与 IPC 面（零 migration / 零新依赖 / 零新通道）、D62 三层入口结构与白名单、确认弹窗；`softDeleteFile` 不补发 `contentChanged`（D61 广播面仅覆盖导入路径，删除路径由调用方 reload 收口）。
- **自动门（2026-09-09 复跑）**：全量测试 95 files / 538 tests passed + 1 skipped（既有）；typecheck、lint 零错误；production build 三端产物；`git diff --check` 通过。
