# V1.8 · 课后反馈常规化（确认已上内嵌反馈 + 录音/转写 AI 整理）实施方案

> 面向实施代理的完整文字规格。交互示意与视觉基准：`tmp/mockups/lesson-feedback-flow.html`（纯 HTML 静态稿，本地不入库，类名与本文一致或接近）。产品负责人于 2026-09-05/06 会话逐屏确认（屏 1 课次行徽标、屏 2 确认弹窗、屏 3 班课、屏 4 编辑态、屏 5 录音/转写 + Skill），并确认 7 个决策点后下达"写方案，V1.8"。本方案即范围授权。

## 0. 摘要

把「写课后反馈」变成「确认本课已上」的一部分，并提供录音转写文字的 AI 整理：

- **确认已上弹窗重做**：在「确认后的 Current Lesson」上方内嵌**课后反馈区**（一对一单学生 / 班课每人一条）；主按钮「保存反馈并确认已上」写完内容才可用（软强制）；跳过需二次确认并明确选原因，跳过后课次行挂黄「缺反馈」徽标可随时补写；
- **反馈可见性**：课次行徽标（已反馈绿 / 缺反馈黄，仅对已上课次显示）+ Viewed Lesson 面板提示条与摘要 + 补写弹窗（复用反馈区组件，纯编辑无确认）；
- **录音 / 转写转反馈**：主路径导入手机录音 App 的转写文字文件（.txt / .md），AI 按所选**反馈 Skill**（复用现有 Skill 机制）或内置默认结构整理成草稿，人工修改后保存；材料用完即弃（不登记 files、不索引、不落库副本）；纯录音上传为后续版本非目标；
- **数据零新增**：反馈就是既有 `notes` 行（`note_kind='manual'` + `student_id` + `lesson_id` + `occurred_on`），学生页「最近学习记录」自动可见（排序已按 `occurred_on` 修复，v1.7.3(V173-fix) `8180b33`）；**零 migration、零新依赖**；
- **新 IPC 仅两条**：`feedback:read-transcript`（选文件读文本，用完即弃）、`feedback:generate`（转写文字 → AI 草稿，不落库）；保存复用既有 `core:create-note` / `core:update-note`，确认复用既有 `core:confirm-lesson-taught`。

## 1. 背景与现状问题

1. 反馈目前只能从「学生」页 →「新增学习记录」进入，与上课动作脱节；高馨云 26 条历史反馈全部来自首次导入，日常新反馈没有顺手入口；
2. 「确认本课已上」弹窗（`confirm-lesson-taught-modal.tsx`）只问下一课，不感知本课反馈是否存在；老师确认后无从发现"这课没写反馈"；
3. 课次行徽标只有 已上/Current/已点名，反馈状态不可见；
4. 老师真实工作流是"课后录音 → 手机 App 转写成文字文件 → AI 整理成反馈 → 手改"，目前应用内无任何承接（现有 AI 网关为 OpenAI-compatible 纯文本通道，DeepSeek 文字整理可直接复用）。

## 2. 决策记录（D39–D45）

实施前将本节原文追加到 `implementation-tasks/V1_8_DECISIONS.md`。

**D39 · 课后反馈并入确认已上（软强制）**
- 产品负责人原话（2026-09-05）："应该需要你写完课后反馈才能记录这节课已上，或者至少要提醒你现在有没有写课后反馈""课后反馈要作为一个比较常规的功能"。
- 采用**软强制**：主按钮「保存反馈并确认已上」仅当反馈区有内容（一对一：非空；班课：≥1 名到课学生有内容）才可用；「跳过反馈，只确认已上」为明确次按钮，点击展开原因单选（本课是自习/考试/答疑；我稍后再写）+ 红色二次确认，防误触。否决硬阻断（会产生为过关而写的垃圾反馈；老师常在课后先确认再当晚细写）。
- 班课有到课学生未写时点主按钮：黄条点名提醒（列出姓名），不阻断；再次点击按"已写的保存、未写的跳过"放行。
- 反馈保存与确认已上是 Renderer 顺序调用（先 note 后 confirm）；中间失败的收敛路径：反馈已存而未确认 → 再次打开弹窗处于"已有反馈"编辑态，主按钮直接确认即可，不产生重复记录（见 D40 幂等）。

**D40 · 反馈数据语义（notes 既有行，零 migration）**
- 反馈 = `note_kind='manual'`，必填 `student_id` + `lesson_id`；`occurred_on` 自动取该课次 `lesson_sessions.scheduled_on`，无排程则取当天本地日期；**不提供手填框**（产品负责人 2026-09-05 确认"自动取排课日期"）。
- **幂等 upsert**：同一 (student_id, lesson_id) 已存在未删除 manual 反馈 → 走 `core:update-note` 更新正文（绝不重复建第二条）；否则 `core:create-note`。判断在 Renderer（overview.notes 可得该学生该课次全部 manual 行；同一课次同一学生允许多条 manual 记录的历史语义保留——学生页手动新增入口不设上限，本弹窗内取"最新一条"作为编辑对象）。
- 用 AI 整理生成并保存的反馈，`ai_metadata_json` 记录来源（skill 快照、transcriptChars、promptVersion、provider/model），复用既有 notes 列，格式按 `FeedbackNoteMetadata` 新合同（轻量字段集，不与 `DraftNoteMetadata` 混用；`isNoteRecord` 对 aiMetadata 的既有校验如与之冲突则以新合同守卫替换并演进钉测）。手写保存的反馈不写 aiMetadata。

**D41 · 班课每人一条 + 请假/缺席可跳过**
- 弹窗反馈区 = 在读学生折叠列表（一对一单学生自动展开、不显示折叠头）；每人一条反馈（学生页按学生聚合，技术上顺）。
- 到课状态来自既有 `attendance.getLesson`（已点名时显示 到课/请假/缺席 徽标；未点名不显示）；请假/缺席学生默认折叠并标"本课请假 · 可跳过"，不强制写。
- 否决"班课一条共享反馈"（学生页按学生聚合，共享反馈无法归属）。

**D42 · 反馈可见性与补写**
- 课次行徽标（仅 `taughtConfirmedAt !== null` 的课次显示；未上课次不显示反馈徽标）：该课全部在读学生均有未删除 manual 反馈 → 绿「已反馈」；任一缺 → 黄「缺反馈」。点击徽标 = 打开补写弹窗。
- Viewed Lesson 面板：已上且缺反馈 → 黄提示条 +「✍ 补写反馈」按钮；已上且有反馈 → 显示最新一条反馈摘要（首行 40 字内 + "已挂到 ×××名下"）。
- 补写弹窗 = 反馈区组件复用（无 Current Lesson 下拉、无确认按钮组，主按钮「保存反馈」）；补写同样支持录音/转写转反馈。
- 学生页零改动（记录自动出现，时间线按 occurred_on 降序，已修复）。

**D43 · 转写文字主路径，材料用完即弃（新 IPC 白名单 = 两条）**
- 产品负责人原话（2026-09-05/06）："反馈现在一般的主流做法是我录下来录音，然后把录音文件上传，最后通过 ai 生成给我的""我那一般是录音转完文字的文件，当然也可以是纯录音"。
- **主路径**：`feedback:read-transcript`（系统文件对话框选 .txt / .md → 读文本返回，**不登记 files 表、不复制进受控目录、不进搜索索引、不落任何库表**）→ `feedback:generate`（{lessonId, studentId, transcriptText, skillId?} → AiGateway.requestText 非流式 → 返回 {draftText, model}，**不落库**）→ Renderer 填入 textarea 人工修改 → 保存才落库。
- **次路径（纯录音）为 V1.8 非目标**：上传纯录音需支持音频输入的语音模型，后续版本在设置页增加独立"语音模型"配置后开启；V1.8 弹窗内该入口渲染置灰态（文案"未配置语音模型"，title 提示后续版本），不实现任何音频逻辑。
- 预算：转写文本上限 `FEEDBACK_TRANSCRIPT_MAX_CHARS = 30000`（超出头部截断并在返回中标注 truncated，UI 提示"已截取前 30000 字"）；输出 `FEEDBACK_MAX_TOKENS = 1500`；费用量级与一次小生成相当。
- 取消/失败：请求进行中可取消（复用 AiGateway AbortController 模式）；失败显示 inline-error 可重试；transcript 文本只存在于请求生命周期，绝不写日志、不进备份。

**D44 · 反馈 Skill 驱动整理 + 默认结构兜底**
- 产品负责人原话（2026-09-06）："课后反馈不一定是模板，大概率是 skills"。
- 反馈区工具行含「反馈 Skill」下拉：列出全部 active Skill（`skills.list`）+「不使用 Skill（默认结构）」；Skill prompt 注入生成 prompt，老师可在既有 Skill 管理页自定义"××· 课后反馈"提示词（结构、语气、落款全自定义），不同课程可配不同 Skill。
- 不选 Skill = 内置默认提示词（固定版本 `FEEDBACK_PROMPT_VERSION`）：三段结构（课堂内容 / 掌握情况 / 作业与下节安排）+ 课次/学生上下文。
- **手写路径完全不经过 Skill 与 AI**；AI 只产出草稿，textarea 修改后保存的永远是老师确认过的内容；所用 skillId 记入 aiMetadata。

**D45 · V1.8 非目标**
- 纯录音上传、语音模型配置、设置页音频通道（后续版本）；
- .docx / .pdf 转写文件（.txt / .md 先行，有需要另立）；
- 反馈定时提醒/通知/待办系统（缺反馈徽标即提醒）；
- 反馈导出/分享给家长、结构化掌握度字段、评分；
- 学生页改版、确认已上/点名/Current Lesson 状态机语义变更、V1.6 冻结的流式/预算语义变更。

## 4. 合同规格（V18-A 实现）

### 4.1 通道

```ts
// src/shared/ipc-contracts.ts 追加
readTranscript: 'feedback:read-transcript'   // 空 payload → { fileName, text, chars, truncated } | null（取消选择返回 null）
generateFeedback: 'feedback:generate'        // GenerateFeedbackRequest → { draftText, model, promptVersion }
```

### 4.2 feedback-contracts.ts

```ts
export const FEEDBACK_TRANSCRIPT_MAX_CHARS = 30000
export const FEEDBACK_MAX_TOKENS = 1500
export const FEEDBACK_PROMPT_VERSION = 'v18-01-v1'
export const FEEDBACK_BODY_MAX_CHARS = 8000   // 反馈正文上限（textarea maxLength）

export interface TranscriptResult {
  readonly fileName: string
  readonly text: string
  readonly chars: number
  readonly truncated: boolean
}

export interface GenerateFeedbackRequest {
  readonly lessonId: string
  readonly studentId: string        // 上下文注入学生姓名；班课逐学生调用
  readonly transcriptText: string
  readonly skillId?: string
}

export interface GeneratedFeedback {
  readonly draftText: string
  readonly model: string
  readonly promptVersion: string
  readonly inputChars: number
}

export interface FeedbackNoteMetadata {
  readonly generatedBy: 'feedback-assistant'
  readonly promptVersion: string
  readonly provider: string
  readonly model: string
  readonly skill?: { readonly id: string; readonly name: string; readonly prompt: string }
  readonly transcriptChars: number
}
```

- 守卫：`isTranscriptResult` / `isGenerateFeedbackRequest` / `isGeneratedFeedback` / `isFeedbackNoteMetadata`（模式与既有 contracts 一致：hasOnlyKeys + 字段类型）。
- `core:confirm-lesson-taught`、`core:create-note`、`core:update-note` 合同零改动。

### 4.3 read-transcript 语义

- Main：`dialog.showOpenDialog`（filters：txt/md）→ 读文件（UTF-8；md 不做任何解析，纯文本）→ 超 `FEEDBACK_TRANSCRIPT_MAX_CHARS` 头部截断 + `truncated: true` → 返回；**不写 files 表、不复制、不索引、不记日志正文**；
- 安全：只读系统对话框选中的单个文件；不落任何持久状态；与 managed-file 流程完全隔离。

### 4.4 generate 语义

- Main `feedback-service.ts`：校验 lesson/student 有效（复用 coreData 快照思路：课次标题、课程标题、学生姓名）；拼 prompt =（skill.prompt 或内置默认提示词）+ 上下文块（学生姓名 / 课程 / 课次 / 反馈日期）+ 转写文本；`aiGateway.requestText(requestId, prompt, FEEDBACK_MAX_TOKENS)` 非流式；返回草稿不落库；
- 错误：AI_NOT_CONFIGURED / AI_UPSTREAM 透传既有 AiGatewayError 语义；Renderer 展示 inline-error，可重试、可取消。

视觉基准 = `tmp/mockups/lesson-feedback-flow.html`（产品负责人已逐屏确认）。本节给结构规则；CSS 值以静态稿为准（tokens 与既有 styles.css 一致）。

### 5.1 反馈状态派生（course-view-model.ts）

### 5.2 课次行与 Viewed Lesson

- Viewed Lesson 面板（`viewed-lesson-panel`）在操作按钮组下方追加反馈区：
  - 已上且缺反馈：`.feedback-alert` 黄条（"本课缺反馈 · 确认已上时跳过了课后反馈"）+「✍ 补写反馈」→ 打开补写弹窗；
  - 已上且有反馈：一行摘要（最新一条首行 ≤40 字 + "已挂到 ×××名下"）；
  - 未上：不显示反馈元素（确认动作本身会进入反馈流）。

### 5.3 确认已上弹窗（重做 confirm-lesson-taught-modal.tsx）

结构（自上而下）：

```
Modal title 确认「课次名」已上 / description（原文案保留）
├─ modal-sec 课后反馈  [徽标本课常规项] hint=保存后自动挂到学生名下，学生页可见
│   ├─ feedback-meta：👤 学生 chip(s) + 📅 反馈日期 <b>自动值</b> <i>自动取排课日期</i>
│   ├─ 工具行：[🎙 录音/转写转反馈] [反馈 Skill select] （见 5.5）
│   ├─ 学生反馈编辑区（一对一=单 textarea；班课=折叠列表，见 5.4）
│   └─ 字数计数（0 字）
├─ modal-sec 确认后的 Current Lesson（原 select 原样）
└─ modal-actions
    ├─ 主按钮 ✓ 保存反馈并确认已上（gating 见下）
    ├─ 次按钮 跳过反馈，只确认已上
    └─ guide 文案（随状态变）
   + skip-reason 展开区（原因单选 2 项 + [仍然跳过，只确认已上(红)] [返回写反馈]）
   + missing-inline 黄条（班课提醒，见 5.4）
```

状态规则：

1. 主按钮可用条件：一对一 `body.trim() !== ''`；班课 ≥1 名到课学生 body 非空（请假/缺席学生不计数）；
2. 已有反馈（upsert 编辑态）：textarea 预填最新一条正文，主按钮文案「✓ 更新反馈并确认已上」，次按钮变「保持原反馈，只确认已上」；
3. 跳过：次按钮 → 展开 skip-reason；「仍然跳过」→ 顺序仅调 `confirmLessonTaught`（不写 note），成功后课次行挂黄「缺反馈」；
4. 主按钮点击：顺序 `createNote/updateNote`（每名有内容学生）→ `confirmLessonTaught`；任一步失败显示 inline-error 停在弹窗内，重试幂等（D40）；
5. 反馈日期展示值 = `scheduledOn ?? 当天本地日期`，作为 createNote 的 `occurredOn` 提交；
6. 无在读学生：反馈区显示 empty 文案"当前没有在读学生，无法写课后反馈"，主按钮退化为「✓ 确认已上」（无 note 调用），不显示跳过次按钮。

### 5.4 班课反馈区

- 每名在读学生一行折叠卡（`attendance.getLesson` 已点名时头部显示 到课/请假/缺席 徽标）；
- 到课学生：未写=黄色边框+「待写」，写入内容后变「已写 ✓」绿态；头部徽章 `N / M 已写`（分母=到课学生数）；
- 请假/缺席学生：默认折叠、虚线边、「本课请假 · 可跳过」；填写内容也会保存（不强制）；
- 点主按钮存在到课学生未写：`.missing-inline` 黄条列出姓名（"还有 ×××没写反馈：点名字补写，或再次点击按已写的保存、未写的跳过"）；再次点击主按钮 → 按已写的保存、未写的视为跳过，继续 confirm。

### 5.5 录音/转写转反馈 + Skill

- 工具行 `[🎙 录音/转写转反馈]` 点击在反馈区内展开 `.rec-flow` 折叠块（受控 state，再点/✕ 收起）：
  - 路径 A `.rec-upload`（主）：说明文案"手机录音 App 的转写文件：.txt / .md；AI 直接按反馈结构整理 · 无需额外配置" + [选择文件…]；点击 → `feedback:read-transcript` → 显示文件 chip（文件名/字数/truncated 提示）→ 自动调 `feedback:generate` → 两段进度（读取转写并整理 → 草稿就绪请人工修改）→ draftText 填入当前学生 textarea，计数与主按钮 gating 即时更新；
  - 路径 B（次）：置灰块"上传纯录音 · 需先在设置页配置语音模型（后续版本支持）"，按钮 disabled；
  - [取消/重新选择材料]：中断请求（AbortController）并清空该学生草稿态（不动已手写内容）；
- 「反馈 Skill」select 列出 `skills.list()` 全部 +「不使用 Skill（默认结构）」；change 时仅影响下一次 generate（已生成草稿不回改）；
- 草稿落位后 textarea 尾部下方显示来源标签"AI 草稿 · 请人工修改"；input 事件检测与 draftText 不一致 → 变"已人工修改 ✓"（绿）；保存成功后消失（状态随 note 落库）；
- 生成中该学生 textarea 输入禁用（避免竞争），其余学生不受影响；班课逐学生独立发起。

### 5.6 补写弹窗（lesson-feedback-modal.tsx）

- 入口：Viewed Lesson 黄条按钮、（已上课次）再次双击进教学内容无入口——仅面板入口；
- 结构 = 5.3 的课后反馈区原样（含工具行/班课折叠），无 Current Lesson 下拉；主按钮「✓ 保存反馈」（同 gating：≥1 到课学生有内容）；无跳过按钮（课已确认，跳过=关闭弹窗）；
- 保存：逐学生 upsert；成功后徽标/提示条即时刷新（overview reload）。
