## D39 · 课后反馈并入确认已上（软强制）

- 产品负责人原话（2026-09-05）："理论上每一节课都需要课后反馈的……应该需要你写完课后反馈才能记录这节课已上，或者至少要提醒你现在有没有写课后反馈。也就是说，课后反馈要作为一个比较常规的功能。"
- 确认已上弹窗内嵌课后反馈区（一对一单学生 / 班课每人一条）；主按钮「保存反馈并确认已上」写完内容才可用；「跳过反馈，只确认已上」为次按钮，需展开原因单选 + 红色二次确认。
- 否决硬阻断（会产生为过关而写的垃圾反馈；老师常课后先确认再当晚细写）；班课到课学生未写时主按钮首次点击黄条点名提醒、不阻断，再次点击按"已写的保存、未写的跳过"放行。
- 反馈保存与确认已上为 Renderer 顺序调用（先 note 后 confirm）；中途失败的重试路径按 D40 幂等收敛，不产生重复记录。

## D40 · 反馈数据语义（notes 既有行，零 migration）

- 反馈 = `note_kind='manual'` + `student_id` + `lesson_id`；`occurred_on` 自动取课次排课日期（无排程取当天本地日期），不提供手填框。
- 同一 (student_id, lesson_id) 已存在未删除 manual 反馈时走 `core:update-note` 更新（幂等 upsert，弹窗内取最新一条为编辑对象）；否则 `core:create-note`。学生页手动新增入口的多条语义保留，不受影响。
- AI 整理生成的反馈在 `ai_metadata_json` 记录来源（skill 快照、transcriptChars、promptVersion、provider/model，新轻量合同 `FeedbackNoteMetadata`）；手写保存不写 aiMetadata。
- 排序沿用 `occurredOn ?? updatedAt`（v1.7.3(V173-fix) 已修复批量导入同刻乱序）。

## D41 · 班课每人一条 + 请假/缺席可跳过

- 弹窗反馈区 = 在读学生折叠列表，每人一条（学生页按学生聚合记录）。
- 到课状态来自既有点名记录（已点名显示 到课/请假/缺席 徽标）；请假/缺席学生默认折叠标"可跳过"，不强制写；填写了内容也照常保存。
- 否决"班课一条共享反馈"（学生页按学生聚合，共享反馈无法归属到个人）。

## D42 · 反馈可见性与补写

- 课次行徽标仅对已上课次显示：全员有反馈=绿「已反馈」，任一缺=黄「缺反馈」。
- Viewed Lesson 面板：已上缺反馈 → 黄提示条 +「补写反馈」；已上有反馈 → 最新一条摘要 + "已挂到 ×××名下"。
- 补写弹窗复用反馈区组件（无 Current Lesson 下拉、无确认按钮）；补写同样支持录音/转写转反馈。学生页零改动。

## D43 · 转写文字主路径，材料用完即弃（新 IPC 白名单 = 两条）

- 产品负责人原话（2026-09-05）："反馈现在一般的主流做法是我录下来录音，然后把录音文件上传，最后通过 ai 经过生成给我的。然后我自己再手改的。这个可以加上"；（2026-09-06）"我那一般是录音转完文字的文件，当然也可以是纯录音"。
- 主路径：`feedback:read-transcript`（系统对话框选 .txt/.md → 读文本返回，不登记 files、不复制、不索引）→ `feedback:generate`（AI 整理草稿，不落库）→ 人工修改 → 保存才落库。
- 纯录音上传为后续版本（需设置页独立语音模型配置）；V1.8 弹窗内该入口置灰渲染，不实现音频逻辑。
- 转写文本上限 30000 字（超出头截 + truncated 标注）；输出 token 上限 1500；转写文本只存在于请求生命周期，不写日志、不进备份。

## D44 · 反馈 Skill 驱动整理 + 默认结构兜底

- 产品负责人原话（2026-09-06）："挺好的，然后课后反馈不一定是模板，大概率是 skills"。
- 反馈区工具行含「反馈 Skill」下拉（全部 active Skill + "不使用 Skill（默认结构）"）；Skill prompt 注入生成；老师可在既有 Skill 管理页自定义反馈提示词（结构/语气/落款），不同课程可配不同 Skill。
- 不选 Skill = 内置默认三段结构（课堂内容 / 掌握情况 / 作业与下节安排）兜底；手写路径完全不经过 Skill 与 AI；所用 skillId 记入 aiMetadata。
