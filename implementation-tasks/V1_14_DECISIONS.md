- 日期：2026-09-14
- 背景：产品负责人实测课件区无任何"从零创建"入口（⋯ 菜单全是加工已有文件的动作），且四组展示下空组长文案/重复树头/全员"外部资料"徽标造成结构性噪音。同日复审追加两条反馈：①老师不应在树里看到一份讲义的每个版本——只显示最新版、历史按需可看；②工具行失衡（沉浸阅读占第一顺位全宽按钮，新建藏在 ⋯）。

## D82 · 新建讲义 = 版本链产物，重名自动顺延

- `files:create-lesson-doc {lessonId, name}` → `createLessonDoc`：requireActiveLesson → 名称 trim + 去控制字符 + ≤80 字（违者 `FILE_SOURCE_INVALID`）→ `nextLectureBaseVersionNumber`（重名自动 `第 N+1 版`，与"设为讲义底稿"同规则）→ `createTextObjectAndRegister("# ${base}\n", "base · 第 N 版.md", lesson link)` → 返回 `{ file, version }`（复用 `isWriteFileVersionResult` 守卫）；
- 备选否决：普通裸 md——与"新建一份讲义"语义不符（还要手动设为讲义底稿才能进 AI 链，多一步）；notes 承载——讲义是文件不是记录。
- 产品负责人拍板：版本链形态。手写讲义与 AI 生成讲义同级（当前徽标/✎编辑/✦修改这份全通）。

## D83 · 双入口 + 创建后直进编辑态

- 入口：①⋯ 菜单"本课"组第一位「＋ 新建讲义」；②讲义组头右侧轻量「＋」（LessonMaterialTree 新可选 prop）。readOnly 均不渲染；
- 名称用既有 `requestText` 应用内输入框（默认名 = 课次标题）；创建成功 → 选中新文件 + 进入编辑态（V19-B 受控 editing）+ notice 提示；contentChanged 补发刷新四组与行动卡计数（V110-A/D61 先例）。

## D86 · 版本链按基名分链 + 历史版本按需入口（2026-09-14 复审拍板）

- **缺陷**：`classifyLessonCoursewareFiles` 把课次下全部 ` · 第 N 版.md` 当一条链，只认"全课版本号最高"者为当前，其余入历史；而 Main 侧版本号（`nextLectureBaseVersionNumber`）按基名独立计数。出现第二条链时（既有：设为讲义底稿起不同基名；D82 新增：新建讲义起自定义名），链头被误判成历史版本藏进底部折叠块，V114-B 的"选中新文件直进编辑"因新文件不在 currentMaterials 而失效。修复并入 V1.14（A 进行中、B 未动，且不修则新功能自带已知坑）。
- **分链规则**：classify 按基名（` · 第 N 版` 去后缀）聚合——每链最高版进 currentMaterials，其余入 history（按链分组）；` · 学生版` 不匹配版本链 pattern，维持既有行为随材料显示。draft-panel 的修改候选/引用候选同受益（同消费 classify）。
- **链头行显示基名**：讲义组树行只显示基名不带版本后缀（链头即最新版；完整版本名保留在历史块/胶囊）。
- **主讲义 = 最近保存的链**：currentVersion 从"全课最高版"改为"各链头中 createdAt 最新"（保存新版本即新建文件记录，链头 createdAt = 链的最近保存时间）；自动选中、「当前」徽标、`currentLectureId` 跟随主讲义链头；hover ✕ 白名单从"唯一当前版"扩展为"全部链头"（移除仍走 ⋯ 红区 + 既有确认）。
- **历史按需**：底部常驻 details 行退役；⋯「本文件」组在"选中链头且链内旧版 > 0"时显示「🕘 历史版本（N）」，点击展开既有 details 形态（标题按链标注，默认展开）；条目内 系统打开/移除 语义不变（removeFile 复用）。
- 备选否决：整课 drawer/弹窗式历史查看——新 UI 形态，超 V1.14 纯 Renderer 重排的体量；维持常驻块——即复审要撤的噪音。产品负责人确认方向（"只需要看到最后一个版本，如果要看得话再设计一个入口"）。
